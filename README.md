You asked AI for one small change. It returned 300 lines, three structs, six helper functions, and a variable named `ctx`.

Excellent. Now you only need to figure out what any of it means.

Auto CodeTutor is built for the rest of us: people who love how fast AI can write code, but would rather not spend the afternoon following it around with a flashlight. It turns an unfamiliar embedded C project into something you can click, trace, question, and actually learn.

> AI changed the code. Auto CodeTutor helps you make it yours.

## Stop Chasing Symbols

We have all lost twenty minutes to a variable that looked simple and turned out to be a field inside a typedef inside a generated header.

With Auto CodeTutor, click a function, variable, macro, type, field, or language keyword and get the useful answer immediately:

- What is it?
- What type does it have?
- Where is it defined and used?
- Where can its value change, and what is assigned to it?
- If it is a struct, union, enum, or macro, what is inside it or what does it resolve to?
- What could be affected if you change it?

No more opening twelve files just to learn that `control.valid` is a flag.

## See the Story, Not the Spaghetti

A giant call graph is technically impressive and emotionally unhelpful.

Auto CodeTutor builds a practical, purpose-oriented execution overview instead. It focuses on the parts that make the product do its real job—measure something, configure hardware, move data, send a packet—and keeps generated or vendor infrastructure visually separate. Select a step to jump back to the code, or select code to see where it belongs in the larger flow.

## Ask About the Project, Not Just a Snippet

Most AI tools know the text you pasted. Auto CodeTutor knows the project you opened.

Ask about the whole firmware, a symbol, or a selected region. Answers are tied to verified, project-relative source locations, so an explanation can take you directly to the code behind it. Add a reference folder and the same conversation can use datasheets, manuals, and PDF page citations instead of relying on confident guesswork.

Chats remain attached to the project, because asking the same question after every restart is not a learning strategy.

## Know Whose Code You Are Reading

Embedded projects are rarely written by one person—or even one tool. Auto CodeTutor helps distinguish:

- code managed by the user,
- generated configuration code,
- vendor RTD/SDK code, and
- code whose origin cannot yet be proven.

When the evidence is uncertain, the app says so. “Probably” is not the same thing as “generated by MEX,” and the UI should not pretend otherwise.

## Built to Remember

Import multiple projects and switch between them without rebuilding your mental model every morning. Auto CodeTutor keeps local indexes, symbol explanations, chats, notes, references, and layout state across sessions. When source files change, refresh the project and re-analyze only what changed.

The goal is simple: spend less time recovering context and more time understanding the system.

## Learn Safely

Auto CodeTutor is a learning workspace first, not an enthusiastic code-rewriting robot.

- The editor is read-only during normal exploration.
- Comment generation is previewed before anything touches a source file.
- A backup is created before comments are applied.
- The operation is blocked if non-comment code tokens would change.
- Static navigation and analysis work without AI.
- AI uses your locally installed Codex or Claude subscription CLI—no API key field and no stored API key.

## Works Beyond One IDE

Auto CodeTutor is designed for folder-based embedded C projects, not for a single IDE or microcontroller family. S32 Design Studio and NXP projects receive extra support for MEX-generated code and RTD/SDK provenance, but the core symbol, data-flow, execution, chat, reference, and learning tools are useful across embedded C codebases.

## Getting Started

1. Run the portable executable.
2. Import an embedded C project folder.
3. Let Auto CodeTutor build the local index.
4. Click the symbol you have been pretending to understand.
5. Open **Execution Overview** for the bigger story, or ask a project-wide question.
6. Optionally add a reference folder containing datasheets and manuals.

For AI explanations, install and sign in to the Codex CLI or Claude CLI with your existing subscription. Auto CodeTutor remains useful as a static code-learning tool without either CLI.

## Your Project Stays Your Project

Imported source code, chat history, notes, references, and analysis caches are not bundled into this repository or the distributed application. Project-specific state is stored locally in `.codetutor-next/` and excluded from Auto CodeTutor's index. If the imported project itself uses Git, add that directory to the project's own `.gitignore` before committing it.

When an AI feature is used, the relevant context is passed through the locally installed CLI you selected and is subject to that provider's service and privacy terms. Auto CodeTutor itself does not request or store an API key.

## Honest Boundaries

Auto CodeTutor performs source-level analysis rather than reproducing every compiler preprocessing and build decision. Function pointers, callbacks, complex macros, and conditional compilation can therefore produce incomplete or multiple possible paths. The app surfaces that uncertainty instead of presenting an educated guess as a verified fact.
